# Environment flags — the audited catalog

Doctrine (CLAUDE.md): **winners are defaults** — naked commands run the tuned path. A flag exists only when it is (a) runtime parameter, (b) machine-specific config, (c) documented rollback seam, (d) diagnostic, or (e) explicitly-blocked experimental door. When an experiment concludes negative or flat, the flag and dispatch arm are deleted — the `research/tune-data/*.jsonl` row is the record, not dead code. The 2026-07-08 flag audit enforced this repo-wide; removed-flag ledger at bottom.

Provenance dates refer to `research/tune-data/rig5090.jsonl` / `g7e-rtx6000.jsonl` rows and
HANDOVER.md sections from that date.

**Coverage, stated honestly** (re-counted 2026-08-07): the tree has ~421 distinct
`env::var("MEMRA_*")` read sites and this file lists ~380. Everything in categories (a)-(c) —
runtime parameters, machine config, rollback seams — is catalogued, and that is the part a
naked run or a rollback depends on. The residue is category (d)/(e) instrumentation that never
changes a default: per-kernel A/B forcers (`MEMRA_Q80_*`, `MEMRA_Q40_*`, `MEMRA_FAW_*`,
`MEMRA_MMQ_X_*`), dump/trace/stat probes (`MEMRA_*_DUMP`, `_TRACE`, `_STATS`, `_JSONL`,
`MEMRA_GRAPH_STATS`, `MEMRA_RESIDENCY_CENSUS`), bench-bin-only inputs
(`MEMRA_PROMPTS_FILE`, `MEMRA_PROMPT_DIR`, `MEMRA_BENCH_QT`, `MEMRA_NMEASURE_REPS`,
`MEMRA_CPU_NATIVE_BENCH*`), build-time nvcc tunables read by `build.rs`
(`MEMRA_MMQ_FOLD_CEILING`, `MEMRA_FA_PP_MINBLOCKS`), and the whole `MEMRA_DFLASH_*` /
`MEMRA_SPEC_DFLASH` experimental draft-head block. Those live at their read sites. Do not read
this file's silence as "the flag does not exist" — grep before concluding a seam is absent
(that mistake is what left `MEMRA_MOE_GDEC_GATE` listed here for a month with zero read sites,
now in the graveyard below).

| flag | default | what it does |
|---|---|---|
| `MEMRA_PP_ONLY` | off | prefill-only timing mode (times `prime_cache` — the pass serving primes with, and the ONLY prefill class that carries the m≥16 GEMM/MMQ hooks; see `MEMRA_PP_NLL`) |
| `MEMRA_PP_REPS` | 1 | prefill repetitions (N-median protocol) |
| `MEMRA_PP_WARMUP` | 1 | prefill warmup runs |
| `MEMRA_PP_LOGITS` | off | `<file>`: under `MEMRA_PP_ONLY`, dump `prime_cache`'s last-row logits as raw LE f32 — the cross-arm drift vector (max_abs / rms_rel / top-k order) for a **prefill-GEMM** arm |
| `MEMRA_PP_NLL` | off | `1`: under `MEMRA_PP_ONLY`, teacher-forced prefill exactness on the prime path — argmax disagreement + mean NLL where **the prompt itself is the tape** (position `i`'s logits score prompt token `i+1`). | `MEMRA_PREFILL_LOGITS` | off | `<file>`: dump the VERIFY-class (`decode_step_t`) batched-prefill logit row as raw LE f32. Cross-arm instrument for a kernel that changes the verify class — **not** for a prefill-GEMM arm (use `MEMRA_PP_NLL` / `MEMRA_PP_LOGITS`) |
| `MEMRA_NMEASURE` | 32 | decode tokens measured after counter reset |
| `MEMRA_FORCE_TOKENS_FILE` | off | run-gen diagnostic: teacher-force numeric token ids from a file so placement A/Bs traverse an identical decode route. Also the decode-side branch-(b) exactness instrument (disagreement count + tape NLL); pair it with a REVERSE-TAPE control run, since a tape that is one arm's own greedy output structurally favours that arm |
| `MEMRA_TURN_TOKENS` | 512 | session-bench: suffix length per turn |
| `MEMRA_HIST_FILE` | required | session-bench: conversation history text file |

## 6. Research platform (MTP-heal, dual-shape)

memra's second shape is a research platform. The first protocol (MTP-heal) measures MTP draft-head
acceptance at FULL PRECISION as the ceiling, then on the NVFP4 daily GGUF — the delta is the quant
hit on drafting. See HANDOVER "MEMRA DUAL-SHAPE".

| flag | what it does |
|---|---|
| `MEMRA_FULL_PREC=1` | FULL-PRECISION LOADER MODE (default OFF). Bypasses the standing loader law (large BF16/F8 → Q8_0/NVFP4 re-encode, the "Float-poison" tripwire — the very re-encodes this mode must NOT do). Everything loads Float; large 2D bf16 matmul weights stay **bf16-resident** (`GpuTensor::FloatBf16`) with dequant-on-use, so the 9B (~18GB bf16) + f32 activations fit 24GB instead of blowing to ~38GB as an all-f32 materialization. Per-slot acceptance for this protocol comes from the existing **`MEMRA_SPEC_STATS=1`** (§4) — its
